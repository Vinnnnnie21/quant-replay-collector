# QRC v1.6 编程会话工程契约

状态：已确认产品决策的实施约束

本文件供每一轮 v1.6 编程会话读取。它约束实现方式，不替代产品方案、领域模型、ADR 或公式规格。

## 1. 开工前必读

任何改动前完整阅读：

- `AGENTS.md`
- `CONTEXT.md`
- `docs\product\v1.6-product-strategy.md`
- `docs\research\v1.6-decision-research-formulas.md`
- 当前任务列出的 ADR
- 当前任务涉及模块的现有代码和测试

先执行 `git status --short`。工作区已有改动属于用户，禁止重置、覆盖、删除或顺手格式化无关文件。若任务与已有改动重叠，先理解差异，再做最小兼容修改。

代码能回答的问题直接检查代码，不向用户反问。只有文档之间真实冲突、需要扩大产品范围或需要不可逆选择时才暂停并请求决定。

## 2. Skill 使用规则

实现功能时使用 `tdd` Skill，严格执行一个行为一轮：

1. 写一个通过公开接口验证行为的测试。
2. 确认测试因缺少当前行为而失败。
3. 写最小实现使其通过。
4. 进入下一个行为。
5. 全部变绿后再重构。

禁止先批量写完全部测试再批量实现。测试不应绑定私有函数、内部调用次数或临时文件结构。自有模块尽量使用真实实现；只在交易所网络、时间、随机数和文件系统等系统 seam 使用受控 adapter。

实现完成后使用 `code-review-skill` 审查当前 diff，至少读取 Python、Qt、架构、通用代码质量、并发和错误处理指引。修复所有 blocking 和 important 问题，重新运行测试。

出现非预期缺陷、死锁、随机失败、性能退化或无法解释的测试回归时，不继续猜测。另开诊断轮并使用 `diagnose` Skill，执行“反馈环 → 复现 → 多个可证伪假设 → 插桩 → 回归测试 → 修复 → 清理”。

发现现有模块没有可测试 seam、接口比实现更复杂或相同知识散落多处时，不在功能任务中顺手大重构。记录具体摩擦，功能变绿后再用 `improve-codebase-architecture` Skill 单独审查。

## 3. 架构约束

- v1.6 保持 Python 3.13、PySide6、SQLite、NumPy、pandas、scikit-learn 的单机桌面架构。
- 不创建独立后端进程，不引入 Rust，不接真实交易 API。
- 研究公式和领域规则放在不依赖 Qt 的深模块中。Qt 页面只调用小接口、渲染状态和发起后台任务。
- 不把新领域逻辑继续塞进 `main_app.py` 或 `analysis_workspace.py`。
- 合并重复事件研究实现。旧模块只允许保留读取兼容或轻量 adapter，不能继续产生新口径结果。
- 新模块应有小接口，隐藏公式、缺失处理、版本和错误模式。不要创建只转发参数的浅模块。
- 调用方和测试通过同一个公开 seam 使用模块。
- 不为只有一个实现且没有变化需求的对象创建假抽象。
- 用户可见操作使用明确的结果对象或领域错误，不通过裸字典和魔法字符串跨层传递状态。
- 基础设施异常在模块 seam 转为带上下文的领域错误，并保留异常链；禁止吞异常或同时在多层重复记录。

## 4. 数据库与文件约束

- SQLite 迁移只增不删，必须兼容 v1.5.2 schema version 6 和真实旧数据库。
- 数据库升级继续使用现有升级前备份机制。
- 缺失、零值和不适用是三种状态，不能互相替代。
- 历史研究对象、模型版本和已发布报告不可原地覆盖。
- 多表写入使用事务。失败或取消后不能留下对外可见的半成品版本。
- 批量写入有界，避免把六个月 1 分钟 K 线一次性复制到内存。
- 测试只使用 `tmp_path`、临时 SQLite 或明确的内存 fixture，禁止读写 `quant_collector_app/data` 中的真实数据库。
- 导出先写临时目录，通过校验后原子发布；取消和失败不得污染上一次成功导出。
- 不把数据库、日志、缓存、测试产物、研究导出、用户设置、绝对本机路径或私密交易数据加入 Git。
- 新增依赖必须同时更新声明和锁文件，并验证 Windows 打包。除已确认的 scikit-learn 外，不擅自增加运行时依赖。

## 5. 研究正确性约束

- `docs/research/v1.6-decision-research-formulas.md` 是公式唯一来源。
- 公式、权重、窗口、距离尺度或缺失语义发生变化时，必须先更新公式版本、算例和 ADR，不能只改代码。
- 决策特征只能读取决策截止点及以前已完整收盘的 K 线。
- 决策特征、相似度、行为模型输出和后验结果分开存储与传递。
- 相似度不等于行为概率；行为选择倾向不等于盈利概率；后验差异不等于策略有效。
- `UNCERTAIN`、`UNLABELED` 和后验复标不能进入主要行为模型。
- 同一独立行情片段不能跨训练、验证和测试，也不能在一个正式盲审批次中重复。
- 所有随机过程保存随机种子。相同输入、配置、版本和种子必须复现相同结果。
- 空头收益、MFE、MAE 和退出延续方向必须有独立测试，不能从多头测试推断正确。
- 证据门槛失败是正常结果。禁止用默认值、回退模型或隐藏失败把它伪装成成功。

## 6. 后台任务与 Qt 约束

- 网络、批量解析、模型训练、匹配、Bootstrap、置换和报告生成不得在 Qt 主线程执行。
- 复用 `BackgroundTaskLifecycle`、`CancellationToken` 和现有 controller/worker 生命周期。
- worker 不读取或修改 QWidget；只接收不可变输入并返回有界结果。
- 每个任务明确处理完成、失败、请求取消和已取消状态。
- 取消必须向下传播，并在安全点停止；不能用强制终止线程代替。
- UI 更新只发生在主线程。防止旧任务结果覆盖新筛选条件，复用 revision 或 single-flight 保护。
- 关闭应用时，任务加入现有安全退出流程。
- 错误信息向用户显示中文可行动说明，日志保留技术上下文且不包含敏感数据。

## 7. UI、汉化与设计约束

- 唯一入口是“数据分析 → 决策研究”，内部为“开仓研究”和“平仓研究”。
- 共用五步、顶部上下文栏、三栏盲审、表格、状态标签、空状态和错误状态模块。
- 使用 `ui_style.py` 中已有颜色、字体、字号、间距和主题令牌。
- 禁止页面私有硬编码颜色、字号、圆角、间距和只适配深色主题的样式。
- 状态不能只靠颜色表达。相似度和行为选择倾向不能使用盈利绿色。
- 所有用户可见标题、按钮、字段、图例、警告、错误、空状态和报告正文使用 `zh_CN` 翻译键。
- UI 不直接显示 `ENTRY`、`REJECT`、`EXIT_NOW`、`HOLD` 等内部值；CSV、JSON 和数据库继续保留稳定英文键。
- 开仓和平仓共享布局和交互模块，但不混用标签、持仓状态和结果解释。
- 保存盲态判断前不得通过控件、tooltip、状态栏、表格排序或 worker payload 泄露来源、真实动作、评分和后验数据。

## 8. 测试要求

每轮至少覆盖：

- 一个通过公开接口运行的端到端 tracer-bullet 测试；
- 当前行为的正常路径；
- 最重要的失败或证据不足路径；
- 数据持久化或任务取消涉及的原子性；
- 既有相关行为的回归。

研究计算补充：

- 公式规格数值算例黄金测试；
- 边界值、缺失值和不适用状态；
- 多空方向；
- 时间截止和未来数据泄漏；
- 固定随机种子复现；
- 独立行情片段隔离。

UI 补充：

- 最小交互测试；
- 翻译键和内部枚举泄漏测试；
- 深色和浅色主题；
- 窄窗口折叠；
- worker 完成、失败和取消后的控件状态。

测试命令按范围逐步执行：

1. 当前新增测试文件。
2. 相邻模块测试。
3. 默认非性能测试集：`pytest -q`。
4. 任务要求的性能、Qt native、自检、打包或发布门。

任何跳过都必须说明原因和剩余风险。禁止为了变绿删除测试、放宽正确断言、把失败测试标记 skip，或更改与任务无关的现有语义。

## 9. 文件管理与提交前检查

- 修改前用 `rg` 查找现有模块和重复逻辑，优先复用。
- 新文件放入最接近领域知识的目录，不建立 `utils2.py`、`helpers_new.py` 等无领域名称文件。
- 单个文件出现多个变化原因时拆分；仅有转发职责的文件应合并或深化。
- 删除临时脚本、调试日志和一次性 fixture；检查 `[DEBUG-` 标记为零。
- 运行 `git diff --check`。
- 运行 `git status --short`，逐项解释本轮文件；不夹带缓存、导出和无关格式化。
- 未经用户明确要求，不执行提交、推送、删除真实数据或清理用户文件。

## 10. 每轮完成报告

结束时必须说明：

- 本轮交付的用户可见行为；
- 关键模块接口和为什么这样组织；
- 数据库或文件格式变化；
- 测试命令及结果；
- 未执行的测试和原因；
- 对旧数据、取消、安全退出、汉化和主题的影响；
- 当前 Git 状态；
- 下一轮依赖是否已经解除。

只有测试通过、当前切片可独立演示、没有必需工作遗漏时才能声称完成。
