## 01. 新获取 K 线附加字段可持久化并审计

```text
你是 QRC v1.6 的资深后端工程师。本轮只交付“新获取 K 线附加字段可持久化并审计”这一条完整切片。

必须调用并遵守 $tdd；实现完成后调用 $code-review-skill 审查当前 diff，修复 blocking 和 important 问题。

工作区：项目仓库根目录

开工前完整阅读：
1. AGENTS.md、CONTEXT.md。
2. docs/product/v1.6-coding-contract.md。
3. docs/product/v1.6-product-strategy.md 的 alpha.1 部分。
4. docs/research/v1.6-decision-research-formulas.md 中原始 K 线字段、缺失语义和交易活跃度部分。
5. ADR 0007、0009、0011、0012、0017。
6. 当前 market_data、storage、storage_core、export 和相关测试。

背景：
交易所 K 线响应已经带有计价币成交额、成交笔数、主动买入基础币数量和主动买入成交额，但当前 SQLite 只保存 OHLCV。旧库 schema version 为 6。缺失值必须保持 NULL，不能写成 0。

目标：
通过现有公开存储接口写入一批新 K 线后，四个附加原始字段可以无损读取和审计；旧数据库升级后仍能正常回放，旧行的新字段为 NULL。

按 TDD 逐个完成：
1. 写一个从旧 schema 6 临时数据库升级、写入新 K 线、再通过公开接口读取的失败测试。
2. 增加只增不删的下一版迁移和必要索引，确认升级前备份机制仍被调用。
3. 让交易所响应解析、领域类型、转换、批量 upsert 和范围读取贯通四个字段。
4. 区分“字段缺失”“字段为 0”“字段不适用”；数据库和 Python 类型均保留这一语义。
5. 防止后续只有 OHLCV 的 upsert 把已经补齐的附加字段擦回 NULL。
6. 通过一个小的公开完整度接口或现有数据质量结果，返回每个字段的已覆盖数、缺失数和覆盖率。
7. 保持现有导出兼容；若扩展机器导出，只添加稳定英文键，不能改旧键。
8. 增加旧库迁移、批量写入、重复写入、NULL/0、读取顺序和回归测试。

约束：
- 不实现网络补齐按钮，那属于下一轮。
- 不计算派生特征。
- 不修改真实数据库，不读取 quant_collector_app/data。
- 不在 UI 层复制字段解析。
- 不新增无领域含义的 helper 文件。
- 不改变现有 OHLCV 调用方的默认行为。

验收：
- schema 6 副本可升级，旧数据完整保留。
- 新响应四字段可 round-trip。
- 缺失不等于 0；已知值不会被缺失 upsert 覆盖。
- 默认 pytest 全绿，git diff --check 通过。
- 完成报告列出迁移版本、公开接口、测试命令和 Git 状态。
```

## 03. 当前研究区间可补齐附加行情

```text
目标：
用户选择 Setup 研究区间时能看到三个周期的完整度；点击“补齐当前研究区间”后，系统自动补齐公式预热和后验窗口，支持进度、取消、重试和部分成功恢复。依赖附加字段的研究操作在不完整时拒绝运行并给出中文差额。

1. 从公开服务写失败测试：输入研究区间和三周期，得到每周期缺失 K 线、缺失字段、缺失时间段和覆盖率。
2. 实现公式版本驱动的区间扩展，自动包含历史预热与后验窗口，处理周期边界和闭合 K 线。

5. 每个成功分块安全写入；后续失败或取消不回滚已确认分块，也不发布错误的“全部完成”状态。

- 不使用强制 terminate QThread。
- worker 不接触 QWidget。

- 不在失败时污染先前成功数据或 UI 状态。

验收：
- 三周期完整度和差额可复现。
- 补齐可取消、可重试、可安全关闭。
- 依赖字段的操作在缺失时拒绝，人工复查不被阻断。
- 默认测试、相关 Qt 任务测试和 git diff --check 通过。
```

## 05. 独立行情片段可自动分组并审计修正

```text
你是 QRC v1.6 的资深研究数据工程师。本轮交付“独立行情片段”的自动分组、存储、审计和人工修正。

必须使用 $tdd；完成后使用 $code-review-skill 审查算法复杂度、时间区间边界、事务和领域接口。

前置条件：轮次 04 已完成。
工作区：项目仓库根目录

必读：
- 通用四份文档。
- CONTEXT 中 Independent market episode 的定义。
- ADR 0014、0019、0022、0023。
- 现有 observation universe、temporal validation、matched baseline 和时间对齐测试。

目标：
任何决策样本都能得到可审计的 episode_id。只要特征或后验时间窗口重叠，即使跨交易对或周期，也属于同一市场级行情片段。用户可以有审计记录地合并或拆分，但不能静默改写历史报告使用的分组版本。

按 TDD 完成：
1. 写区间重叠的 tracer test，覆盖同品种、跨品种、跨周期、首尾相接和完全分离。
2. 以可解释、确定性的区间合并算法生成 episode；保存分组公式版本和输入范围。
3. 避免 O(n²) 全量比较，使用排序扫描或等价的有界算法。
4. 建立人工合并/拆分命令和不可变审计记录；旧模型和报告继续引用原分组版本。
5. 在样本复查或研究状态区提供片段数量、组成、自动/人工来源和修正入口。
6. 所有训练、批次、匹配调用同一个 episode 接口，禁止各自重写分组。
7. 测试确定性、时区、闭区间/开区间边界、修正事务失败和历史版本读取。

约束：
- 不按 session_id 或 symbol 简单当作独立证据。
- 不允许用户修改分组后自动覆盖已发布研究。
- 不让 Qt 了解区间合并实现。

验收：
- 重叠规则跨品种和周期一致。
- 自动分组可复现，人工修正可审计。
- 下游只依赖一个公开 episode 接口。
- 默认测试和复杂度基准通过。
```

```text
按 TDD 完成：

- 可从实际 OPEN 完成一次不泄漏的盲审。
- 三周期都严格截止。
- 原始动作、盲态判断、揭示和复标可审计。
```

## 07. 已揭示样本可审计三周期结构相似度

```text

必须使用 $tdd；完成后使用 $code-review-skill 审查公式忠实度、数值稳定性、性能和接口深度。

前置条件：轮次 01、03、06 已完成。
工作区：项目仓库根目录

- 通用四份文档，尤其完整公式规格第 2—8、15 节。

给定同一 Setup 版本、同方向的两个已揭示样本，公开研究接口返回总相似度、市场/日历差异、三个周期和四个特征组分解、完整度与不可计算原因。UI 在自由浏览区展示，结果不能进入正式证据。
```

## 3. 异常专用 Prompt

以下 Prompt 不属于正常开发顺序，只在某轮出现疑难问题时使用。

### A. 缺陷或随机失败诊断

```text
请使用 $diagnose 处理当前 QRC v1.6 缺陷。不要先改代码。

工作区：项目仓库根目录
先阅读 AGENTS.md、CONTEXT.md、v1.6-coding-contract.md、关联 ADR 和引入缺陷的任务文档。

必须：
1. 建立快速、确定、Agent 可运行的失败反馈环。
2. 多次确认复现的是用户描述的同一个问题。
3. 给出 3—5 个按概率排序且可证伪的假设。
4. 每次只验证一个变量，调试日志统一使用唯一 [DEBUG-xxxx] 前缀。
5. 在正确 seam 写回归测试，确认先失败。
6. 做最小修复，重跑最小反馈环和相关回归。
7. 删除全部调试代码、临时脚本和日志。
8. 说明根因、为什么现有测试漏掉，以及是否暴露架构问题。

禁止没有反馈环就猜测修复，禁止吞掉异常或放宽测试。
```
