# QRC v1.6 产品策略与推动方案

状态：已确认
日期：2026-07-18
产品边界：本地个人交易研究工具

## 1. 结论

v1.6 的主线不是增加更多传统技术指标，也不是直接生成自动交易策略。它要把用户在回放中的主观开仓和平仓判断，转成可复查、可计算、可验证、可版本化的行为证据。

正式版必须交付两条完整链路：

1. 开仓研究：我在什么结构下愿意开仓或拒绝开仓，判断后的价格路径是否存在差异。
2. 平仓研究：我在什么市场和持仓状态下愿意立即退出或继续持有，判断后的价格路径是否存在差异。

v1.6 的最终产物是“量化行为画像”和“待验证策略假设”。只有以后完成开平仓联合规则、交易成本、仓位风险、真正未触碰的前瞻验证和失效监控，才允许称为可交易量化策略。

## 2. 产品目标

### 2.1 用户问题

v1.6 要帮助用户回答：

- 我反复交易的 Setup 到底是什么，而不是事后用一句话概括。
- 同一种 Setup 下，我为什么有时开仓，有时拒绝。
- 哪些客观市场结构与我的选择稳定相关。
- 我的开仓和平仓判断，是否在结构相近的样本中对应不同的后续路径。
- 当前证据处于样本不足、探索、正式研究还是待前瞻验证阶段。
- 下一批最应该复查哪些样本，而不是随机看 K 线。

### 2.2 成功标准

v1.6 成功不以“找出一条赚钱策略”为标准。正式验收看以下结果：

- 任一研究分数都能追溯到公式版本、原始字段、样本和模型版本。
- 相同数据、参数、应用版本和随机种子可以复算出相同报告。
- 缺失数据不会被伪装成零，数据不足不会被伪装成结论。
- 用户可以从一个 Setup 版本完成盲审、相似检索、行为建模、后验比较和报告发布。
- 开仓和平仓共享研究基础设施，但不混用标签、持仓状态或结果解释。
- 未通过策略验证的结果不会出现在实盘页、自动下单或买卖提醒中。

## 3. 当前代码诊断

现有代码已经具备回放、模拟交易、事件存储、研究导出、时间验证、候选选择和报告基础，不需要重写产品。

必须先处理的缺口：

- Binance K 线响应已经包含计价币成交额、成交笔数、主动买入基础币数量和主动买入成交额，但当前 SQLite K 线缓存只保留 OHLCV。
- `quant_collector_app/event_study.py` 与 `quant_collector_app/research/event_study.py` 存在重复事件研究实现，UI 还有多个入口。
- 当前事件研究把开仓和平仓放在近似相同的页面和计算语义中。
- 现有 entry logic research 已有候选池、相似研究和时间验证基础，但没有形成生产级的完整交互闭环。
- 研究 UI 主要集中在大型工作区文件中。v1.6 不能继续把领域公式和状态塞进 Qt 页面。

这些问题应通过数据迁移、服务收敛和垂直切片解决，不通过 Rust 重写解决。

## 4. 明确范围

### 4.1 v1.6 包含

- 四个 K 线附加原始字段的持久化、质量检查和区间补齐。
- Setup 库、不可变 Setup 版本和三层周期画像。
- 开仓与平仓决策事件、盲态判断和后验复标审计。
- 基于已确认样本的结构相似候选，不生成随机拒绝样本。
- 可解释的弹性网逻辑回归行为模型。
- 按时间和独立行情片段隔离的验证。
- 开仓 `ENTRY/REJECT` 和平仓 `EXIT_NOW/HOLD` 的匹配后验比较。
- 不可变模型版本、研究快照和策略假设卡。
- 决策研究工作区的完整汉化和统一设计系统。

### 4.2 v1.6 不包含

- 订单簿、深度图、逐笔成交或真实订单流。
- 连接交易所订单 API、自动交易或真实持仓管理。
- 黑盒模型、图像形态识别或用大模型直接猜交易规则。
- 自动把未开仓 K 线标成 `REJECT`，或把未平仓时点标成 `HOLD`。
- 从第三方交割单直接复原其不可见的主观决策。
- 开平仓联合策略回测、资金管理、组合优化和策略失效调度。
- Rust 后端重写和 PDF 渲染链。

## 5. 用户工作流

### 5.1 研究对象

用户先选择：

- Setup 版本；
- 多头或空头方向；
- 一个决策周期和两个更高背景周期；
- 研究数据区间。

顶部上下文栏持续显示这四项，以及两类样本数、独立行情片段数、数据完整度和研究成熟度。

### 5.2 五步研究

| 步骤 | 回答的问题 | 主要操作 | 证据门槛的表现 |
|---|---|---|---|
| 样本复查 | 当时我会怎么判断 | 三周期盲审、理由、信心、备注 | 页面始终可用 |
| 相似候选 | 哪些位置与已确认行为相似 | 检查总体候选、生成正式盲审批次 | 数据不完整时拒绝生成 |
| 行为模型 | 哪些指标稳定影响我的选择 | 用户触发训练、比较不可变版本 | 不稳定时保存失败实验 |
| 后验对比 | 判断后路径是否存在可靠差异 | 查看完整 15 项矩阵和敏感性 | 样本不足时不执行正式推断 |
| 版本报告 | 当前研究究竟得到什么 | 查看草稿、发布不可变快照 | 任何成熟度均可发布 |

五步可以自由切换。证据不足只限制不成立的操作，不隐藏页面，也不强制用户按“下一步”。

### 5.3 盲审

样本复查采用三栏布局：

- 左栏：批次、匿名样本列表和完成进度；
- 中栏：决策周期主图，以及下方并排的两个更高周期图；
- 右栏：人工判断、理由、信心、备注和保存。

保存前只显示决策截止点及以前的信息。样本来源、真实动作、相似度、模型分数、入队原因、未来 K 线和最终盈亏全部隐藏。保存后才允许揭示，并把后验修改另存为复标版本。

### 5.4 相似候选

相似候选页展示候选总体数量、行情片段覆盖、完整度、相似度分布和批次构成，不展示未判断样本的逐条排行榜。

正式批次由系统按当前阶段的高相似、边界和多样性比例组建，每批最多 20 条且同一行情片段最多一条。自由浏览中提前揭示的候选永久排除出主要模型和正式匹配推断。

### 5.5 行为模型

开仓输出称为“开仓选择倾向”，平仓输出称为“立即平仓选择倾向”。页面固定说明它们描述用户过去的选择规律，不表示未来收益。

模型页必须展示：

- 版本、训练截止时间、样本和行情片段；
- 探索或正式验证状态；
- 稳定指标的中文名称、方向、系数和跨折稳定性；
- 时间外召回率、精确率、类别平衡对数损失、阈值和校准；
- 适用范围和超出范围的候选；
- 没有稳定指标或稳定阈值时的真实失败原因。

### 5.6 后验对比

后验页固定展示 1、3、5、10、20 根 K 线下的方向调整收盘收益、MFE 和 MAE，共 15 项。主结论来自匹配样本和行情片段级推断，未匹配总体均值只作描述。

正式状态只有：

- 可比样本不足；
- 当前样本未发现可靠差异；
- 当前样本存在差异证据。

页面不挑选最好看的窗口，报告也不能只导出显著项。

### 5.7 版本报告

应用内报告使用结构化中文视图。用户主动发布后生成不可变研究快照。

导出包包含：

- 中文 Markdown 总报告；
- 英文字段的 JSON manifest；
- 样本、系数、验证和完整 15 项后验结果 CSV；
- 报告图表 PNG；
- 公式版本、应用版本、数据区间、随机种子和文件哈希。

证据不足和失败实验也允许发布，不能通过不保存失败结果制造幸存者偏差。

## 6. 数据与研究规则

公式、符号、固定权重、距离尺度、缺失处理、统计检验和数值算例以 `docs/research/v1.6-decision-research-formulas.md` 为唯一来源。本方案不复制另一套公式。

实现时必须保持以下边界：

- 决策特征只读取已完整收盘的 K 线。
- 决策特征、结构相似度、行为倾向和后验结果分开存储。
- 同一 Setup 版本只与同方向样本比较。
- 三层周期属于 Setup 版本，保存后修改周期必须创建新版本。
- 相似度是复查优先级，不是行为概率或盈利概率。
- 行为模型使用人工确认的明确标签，`UNCERTAIN` 和 `UNLABELED` 不进入训练。
- 独立行情片段是抽样、验证、匹配和推断的独立单位。
- 所有随机过程保存种子，所有模型与报告不可变。

## 7. 技术落点

v1.6 继续使用 Python 桌面栈，不引入独立后端。建议按下面的责任边界实施，具体文件名可以在开发前微调。

### 7.1 研究领域层

在 `quant_collector_app/research/` 下建立单一决策研究模块，负责：

- Setup 与决策事件领域对象；
- 三周期特征和完整度；
- 结构相似检索；
- 开仓和平仓行为模型；
- 后验路径、匹配和统计推断；
- 模型、实验和报告 manifest。

旧事件研究实现只能作为读取兼容层或迁移适配器，不能继续生成新口径结果。

### 7.2 服务与任务层

由一个决策研究服务向 UI 提供小而稳定的用例接口。耗时操作包括：

- 附加行情补齐；
- 候选扫描；
- 模型训练与时间验证；
- 全局匹配、Bootstrap 和置换；
- 报告导出。

这些操作全部复用现有后台任务生命周期，支持进度、取消、失败恢复和安全退出。Qt 控件不参与公式计算。

### 7.3 持久化层

数据库迁移只增不删，至少承载：

- K 线附加原始字段及其缺失状态；
- Setup 和不可变 Setup 版本；
- 决策事件、原始动作和版本化人工判断；
- 盲审批次、揭示状态和排除原因；
- 不可变模型与标准化参数；
- 匹配研究、统计结果和研究快照。

升级前继续创建数据库备份。旧事件、旧标注和旧报告保持可读。

### 7.4 UI 层

唯一入口为“数据分析 → 决策研究”，内部使用“开仓研究”和“平仓研究”标签页以及共用五步组件。

页面复用 `ui_style.py` 的主题、字体、间距和语义色，复用现有 K 线图表和翻译体系。禁止页面私有硬编码颜色、字号、圆角和间距。缺少 `zh_CN` 键、裸露内部枚举值和绕过设计令牌的样式都应进入发布检查。

## 8. 版本推动顺序

### 8.1 v1.6.0-alpha.1：数据基础

交付：

- 四个附加 K 线字段的存储和向后兼容迁移；
- 当前研究区间补齐、全量维护入口、进度与取消；
- 三周期完整度审计；
- 公式内核、数据截止规则和数值算例测试；
- 新旧数据库备份和迁移回归。

退出条件：

- 旧 OHLCV 行保持可用且新增字段为空而不是零；
- 已补齐区间可复算出稳定原始字段；
- 三周期任一缺失时，正式研究计算给出具体中文原因；
- 普通回放不因研究字段缺失而失效。

### 8.2 v1.6.0-alpha.2：决策样本

交付：

- Setup 库、不可变版本和三层周期画像；
- 开仓与平仓决策事件；
- 原始动作、盲态判断、揭示和后验复标；
- 正式盲审批次；
- 三栏工作台；
- 旧事件入口合并与旧数据兼容。

退出条件：

- 保存前无法通过 UI 或服务载荷读取后验字段和候选来源；
- 揭示后的修改不会覆盖原始判断；
- 同一行情片段不会在同一批次重复出现；
- 开仓和平仓标签和中文解释不会串用。

### 8.3 v1.6.0-alpha.3：开仓研究闭环

交付：

- 三周期市场结构与日历相似度；
- 相似候选总体审计和正式批次；
- 开仓弹性网行为模型；
- 行情片段隔离的时间验证与适用范围；
- `ENTRY/REJECT` 匹配后验比较；
- 开仓模型版本和研究报告。

退出条件：

- 公式数值测试与规格算例一致；
- 少于门槛时系统拒绝正式分数或推断；
- 相同输入和种子生成相同模型及统计结果；
- 空头方向的收益、MFE 和 MAE 通过独立回归测试；
- UI 不把开仓选择倾向称为收益概率或信号。

### 8.4 v1.6.0-beta.1：平仓研究闭环

交付：

- 持仓状态特征和持仓片段；
- 平仓相似候选；
- 平仓弹性网行为模型；
- `EXIT_NOW/HOLD` 匹配后验比较；
- 账户压力的独立描述区；
- 平仓模型版本和研究报告。

退出条件：

- 只研究全量平仓，不把部分减仓混入；
- TP/SL 未设置与字段缺失严格区分；
- 账户压力不进入主相似度和主行为模型；
- 平仓结果解释正确区分错过的有利空间和避开的不利空间；
- 未关联原始开仓 Setup 的旧平仓不能进入正式模型。

### 8.5 v1.6.0-rc.1：产品化验收

交付：

- 策略假设卡；
- 草稿与不可变版本报告；
- Markdown、JSON、CSV、PNG 导出；
- 全量中文、设计系统和多主题检查；
- 大数据性能基准、取消、安全退出和错误恢复；
- v1.5.2 回放、交易记录、分析和导出回归。

退出条件：

- 所有新界面和人类报告完成中文检查；
- 全部新控件跟随支持的主题，状态不只靠颜色表达；
- 已发布报告可通过 manifest 和哈希复核；
- 现有核心流程无阻断性回归；
- Windows 打包、自检、数据库升级和干净发布检查通过。

### 8.6 v1.6.0：正式版

只有开仓和平仓两条研究链全部通过 rc 验收才发布。alpha 和 beta 用于本地真实样本试用，不承诺研究结果稳定，也不能升级为正式策略结论。

## 9. 测试与发布门

### 9.1 研究正确性

- 公式规格中的数值算例全部成为黄金测试。
- 多空方向、时间截止、三个周期对齐和缺失语义分别测试。
- 验证集、最终测试集和行情片段隔离设置泄漏测试。
- Bootstrap、置换和批次抽样设置固定种子复现测试。
- 15 项多重检验必须整体校正，不能逐项计算后漏掉非显著结果。

### 9.2 数据安全

- 使用真实旧版本数据库副本执行只增迁移测试。
- 升级前备份、取消补齐、网络失败和重复补齐均做回归。
- 本地真实交易数据不进入仓库、测试夹具或发布包。
- 删除、覆盖和自动重训都需要明确的产品操作，不允许后台静默发生。

### 9.3 UI 与汉化

- 扫描新增用户文本是否全部进入翻译资源。
- 扫描内部枚举、异常码和英文字段是否直接显示。
- 扫描决策研究页面的硬编码颜色和尺寸。
- 深色、浅色和现有自定义主题执行截图检查。
- 1920×1080 为主要工作台验收尺寸；较窄窗口验证左栏折叠和关键操作可见。

### 9.4 性能与稳定

alpha.1 在现有“六个月 1 分钟 K 线”参考场景上记录基准，冻结 v1.6 的候选扫描、训练、匹配和报告预算。任何超预算任务先分析、向量化、索引和缓存，再评估局部底层优化。

所有重任务必须：

- 不阻塞 Qt 主线程；
- 有进度或明确的不可估算状态；
- 可请求取消；
- 失败后保留已确认安全的数据；
- 关闭应用时进入安全停止流程。

## 10. 主要风险

| 风险 | 表现 | 控制 |
|---|---|---|
| 样本少却输出复杂模型 | 系数漂移、阈值偶然 | 指标数量上限、时间验证、稳定性门槛 |
| 事后标签污染 | 用户看见结果后修改判断 | 盲审、揭示状态、复标版本、正式排除 |
| 随机拒绝样本 | 模型只学会“离 Setup 很远” | 结构相似候选、正式匹配 |
| 多次挑选最好结果 | 报告只剩显著窗口 | 固定 15 项、统一 BH、完整导出 |
| 缺失字段被当成零 | 活跃度特征产生假信号 | 原始空值、完整度门、拒绝计算 |
| UI 暗示研究分数能赚钱 | 高分显示成绿色信号 | 研究语义色、固定风险说明 |
| 双语言或重写失控 | 开发时间消耗在基础设施 | v1.6 固定 Python 栈，Rust 仅看性能证据 |
| 入口和实现继续分叉 | 同一事件得到不同结果 | 单一工作区、单一决策研究服务 |

## 11. v1.7 接口

v1.6 的策略假设卡是 v1.7 的输入候选，不是自动升级的策略。v1.7 才考虑：

- 把已冻结的开仓和平仓规则组合为可执行规则；
- 加入手续费、滑点、资金费率和执行时点；
- 加入仓位、止损、组合风险和最大暴露；
- 在更晚、未参与归纳的数据上前瞻验证；
- 比较多个策略假设的相关性和组合贡献；
- 监控行为边界、市场结构和绩效是否漂移。

任一策略假设未满足 v1.7 门槛时，应继续留在研究状态，而不是为了增加策略数量强行上线。
